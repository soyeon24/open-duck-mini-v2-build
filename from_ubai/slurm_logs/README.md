## 로그에서 나온 것 1 — 보상이 실제 성능을 안 따라갔다

`.out` 에 `STEP: <스텝> reward: <값>` 이 남아 있습니다. 기립 3종의 최종값:

| 정책 | 잡 | 최종 학습 보상 | `eval_standup.py` 성공률 (45도 이상) |
|---|---|---|---|
| v2 | 900147 | **85.1** | 0/8 |
| v3 | 900201 | 83.0 | 0/8 |
| v4 | 901992 | 76.4 | 0/8 |

**보상이 제일 높은 v2 가 실제로는 제일 낫지도 않습니다. 셋 다 똑같이 0% 입니다.**

그럴 만합니다. 구버전 보상표를 에피소드 전체에 대입해 보면 (`episode_length` 1000, dt 0.02):

```
가만히 누워만 있으면   60.0   (upright 2.5 + alive 0.5)
처음부터 서 있으면    260.0
실제 v2 85.1 -> 누움~서있음 구간의 12.5% 지점
     v3 83.0 ->                      11.5%
     v4 76.4 ->                       8.2%
```

즉 **받은 보상의 70% 이상이 그냥 누워 있어서 나온 것**이고, 셋은 나머지 200점 중 20점쯤을
가져간 상태에서 멈췄습니다. 누워 있는 동안 `upright` 와 `alive` 말고 전부 0 이었던
문제(`SIM_NOTES.md` 발견 7)가 학습 곡선에 그대로 찍혀 있습니다.

→ **학습 보상만 보고 "잘 되고 있다" 고 판단하면 안 됩니다.** 태스크 성공률을 따로 재야 합니다.

## 로그에서 나온 것 2 — 실제 에피소드는 10초가 아니라 20초였다

PPO 파라미터에 `'episode_length': 1000` 으로 찍혀 있습니다. `standup.py` 의
`config.episode_length = 500` 은 **학습에 안 쓰입니다** — brax 의 `ppo.train` 이
`brax_ppo_config` 의 값을 받아가기 때문입니다.

지금까지 "10초" 로 알고 있었는데 실제로는 **20초**로 돌고 있었습니다. 기립에는 오히려
넉넉한 쪽이라 급한 문제는 아니지만, 설정 두 군데가 다른 값을 말하고 있는 건 정리해야 합니다.
